# Wallume 第四阶段第三批：锁屏、性能与设置设计

日期：2026-07-17

## 范围

本批交付应用内锁屏同步、性能状态与短时诊断、基础设置三个页面。三个子系统按 Lock Screen、Performance、Settings 的顺序实施，各自具有独立服务、状态模型、错误边界和测试门禁，最终作为第四阶段第三批统一验收并本地合并。

本文件规定跨子系统架构、生命周期和统一验收边界。各子批的实现契约分别记录在同日的锁屏同步、性能诊断和设置页面子规格中；子规格不得放宽本文件的安全与隐私约束。

本批不实现音量控制、语言切换、缓存清理、图库重建、完全重置或最终本地化。锁屏播放继续使用媒体库已有的静音 HEVC 变体和封面。现有 `wallume-restore` 与 `wallume-runtime` 保留为独立恢复和诊断工具，应用 UI 不通过子进程驱动它们。

## 总体架构

`WallumeApp` 在进程内分别持有 `LockScreenSyncService`、`PerformanceDiagnosticsService` 和 `SettingsStore`。服务复用现有 Core 安全事务、恢复器、运行时快照、文件 IO 和采样能力，但只通过窄接口向 SwiftUI 发布不可变状态。页面不直接读写系统文件，也不直接管理定时器或登录项。

`ApplicationController` 负责构造服务并连接现有媒体库、显示器分配、运行时状态和应用生命周期。三个服务的错误状态彼此隔离：锁屏错误不停止桌面播放，性能错误不改变运行时，设置错误不损坏已保存的有效偏好。

三个子批依次交付：

1. 锁屏同步服务、配置存储和 Lock Screen 页面。
2. 实时性能采样、30 秒诊断会话和 Performance 页面。
3. 强类型设置存储、登录项适配器、诊断导出和 Settings 页面。

## 锁屏同步

### 状态模型

锁屏功能公开以下互斥状态：未配置、检测中、可配置、等待主显示器壁纸、同步中、已同步、正在恢复、需要修复、系统版本不支持。状态快照同时携带已选 Aerial 槽、最近同步媒体、最近事务、备份校验摘要、最近错误和可用操作。

### 首次设置

首次进入页面只执行 `LockScreenProbe` 的只读探测，展示：

- 当前 macOS 代际及是否允许写入；
- Aerial manifest、`Index.plist` 和视频目录是否可用；
- 已下载的安全候选槽；
- 外部 sidecar 或备份冲突。

如果没有候选槽，页面引导用户打开系统壁纸设置下载并选择一个动态壁纸，返回后由用户主动刷新。Wallume 不自动选择第一个槽。用户必须明确选择一个候选槽，并在确认界面看到将修改的专用视频槽、`Index.plist` 节点、锁屏封面以及恢复保障，确认后才能启用同步。

### 配置与事务权威

锁屏偏好保存为独立、版本化、原子写入的 JSON，包含是否启用、明确选择的 Aerial ID、当前活动事务 ID、最近同步媒体 ID、最近同步时间和最近结果。活动事务 ID 只是指向权威事务日志的引用；该配置只表达用户意图和 UI 状态。

现有 `LockScreenTransactionManifest` 仍是系统写入与恢复事实的唯一权威记录。配置文件不得复制备份所有权、目标哈希或恢复阶段。配置损坏时保留原文件、停止新写入并显示需要修复；不得自动覆盖损坏配置。

服务启动时必须先调用 `RecoveryCoordinator.inspect()` 对齐配置引用和事务日志，再允许自动同步。活动事务处于 `prepared`、`writing` 或 `restoring` 时先完成保守恢复，再根据当前主显示器重新同步；`committed` 且与配置引用一致时继续作为当前锁屏状态；`conflicted` 或存在多个无法唯一归属的活动事务时进入需要修复并禁止新写入。如果事务已提交但应用在保存活动事务 ID 前崩溃，服务只能在“唯一候选、Aerial ID 与用户已选槽一致”时自动恢复到原始状态后重新同步，否则必须等待用户处理。

### 自动同步

启用后，服务观察完整显示器快照、主显示器分配和媒体库状态。主显示器存在可用媒体时，服务使用媒体库现有 `variantURL` 和 `coverURL` 构造 `LockScreenTransactionRequest`，在串行命令通道内执行事务。

- 相同媒体已经成功同步时不重复写入。
- 主显示器变化或其壁纸更换时自动同步新媒体。
- 主显示器没有分配、暂时离线、媒体缺失或媒体文件不可用时进入等待状态，不执行系统写入，也不自动恢复。
- 等待条件解除后自动重新评估并同步。
- 未知 macOS 版本、外部 sidecar、路径异常、备份异常、写入验证失败或恢复冲突会阻止后续新写入。
- 锁屏同步失败不回滚桌面分配、不暂停桌面播放。

现有事务禁止覆盖先前的恢复材料，因此切换到不同媒体时必须使用保守的“先恢复、再安装”流程。服务先依据活动事务 ID 调用 `RecoveryCoordinator`，验证原始 Aerial 视频、封面和 `Index.plist` 已完整恢复；只有恢复无冲突后才为新媒体创建全新事务。恢复与新安装都在串行命令通道内执行。若应用在两步之间退出或崩溃，系统停留在已验证的原始状态，重启后可重新同步；绝不直接用第二次安装覆盖第一次事务的备份。

### 关闭与恢复

关闭同步不是简单清除开关，而是显式恢复操作。服务调用 `RecoveryCoordinator` 恢复当前 Wallume 锁屏事务，并验证专用槽、封面和 `Index.plist` 都回到原始状态。只有恢复验证成功后才保存为关闭状态。

如果当前文件已被外部修改、备份不一致或恢复发生冲突，服务进入需要修复状态，保留事务日志和全部必要备份，不宣称已关闭。桌面播放保持运行。页面提供重新检测、重新同步、恢复系统壁纸、打开系统壁纸设置和导出本地诊断。

## 性能页

### 实时状态

Performance 页面存在时启动轻量采样，页面销毁时立即停止。每秒采样一次，数据只保存在内存中，不写磁盘。页面展示：

- 当前进程 CPU 和 RSS 内存；
- 活动显示器与播放会话数；
- 共享播放器数量和引用数；
- 当前有效暂停原因；
- 最近 60 秒样本的平均值和峰值。

实时采样不得控制、重启或重新配置播放器，不得在页面关闭后留下常驻定时器。

### 30 秒短时诊断

短时诊断必须由用户主动启动，固定持续 30 秒并每秒采样一次。运行中显示进度和取消操作。取消会终止采样且不生成完成报告。

完成后原子保存一个版本化 JSON 报告，包含：

- 开始时间、持续时间、样本数和诊断场景；
- CPU 平均值与峰值；
- RSS 平均值与峰值；
- 活动显示器、播放会话、播放器资源和引用关系摘要；
- 暂停原因摘要；
- 芯片、物理内存和 macOS 版本。

报告不得包含媒体内容、媒体名称、缩略图、视频文件或不必要的用户绝对路径。页面展示最近一次报告，并允许用户通过保存面板导出 JSON；报告不自动上传。

### 当前机器参考结果

当前开发机器的实际 30 秒诊断结果作为本阶段性能参考，并且不阻塞第三批完成。报告和阶段文档必须记录具体芯片、内存、macOS 版本与测试场景，不得将结果描述为 M1 数据。

原设计中的基础款 M1、macOS 14 指标保留为未来兼容性基线，不再作为本批完成门槛。性能页使用“当前设备参考结果”表述，不把缺少 M1 设备显示为失败或未认证。

## 设置页

### 强类型偏好

`SettingsStore` 使用强类型快照管理：

- `launchAtLogin`：默认关闭；
- `openGalleryAtLaunch`：默认关闭；
- `pauseInLowPowerMode`：默认开启。

普通偏好使用稳定的 `UserDefaults` 键。登录启动通过独立的 `LoginItemControlling` 接口和生产 `SMAppService` 适配器实现。登录项系统调用失败时，Store 保留之前的有效状态并显示错误，不发布虚假的成功值。

`openGalleryAtLaunch` 复用现有启动逻辑，修改后在下次启动生效。`pauseInLowPowerMode` 修改后立即重新计算运行时环境；监控器继续检测系统低电量状态，但只有偏好开启时才加入 `.lowPower` 暂停原因。

### 信息与诊断

设置页展示应用版本、数据目录和诊断目录，并提供 Finder 打开入口。统一诊断导出包含：

- Wallume 构建与系统摘要；
- 脱敏后的设置摘要；
- 锁屏功能状态和最近事务摘要；
- 最近性能诊断报告；
- 当前应用错误摘要。

诊断导出不得包含媒体文件、视频内容、缩略图、系统备份内容或未脱敏的用户主目录。用户通过保存面板明确选择输出位置；应用不执行后台网络请求或自动上传。

## 生命周期与数据流

应用启动时先加载设置，再创建受设置影响的运行时环境策略；随后加载显示器分配和锁屏配置，启动桌面运行时及锁屏观察。主窗口关闭会销毁 SwiftUI 页面和页面级实时性能采样，但不会停止桌面运行时或已启用的锁屏观察。

30 秒诊断由应用级服务持有，因此用户切换页面时诊断可以继续；正式退出应用会取消尚未完成的诊断，不生成完成报告。锁屏事务或恢复正在进行时，退出流程必须等待当前不可中断的文件操作到达安全终点，再终止服务。

应用正式终止时停止设置与显示器观察、取消性能采样、等待锁屏命令安全完成，然后按现有顺序停止桌面运行时。独立 `wallume-restore` 在应用不可用时仍能执行保守恢复。

## 错误处理

- 锁屏配置读取失败：保留文件、禁止新写入、显示需要修复。
- 锁屏同步失败：保留桌面状态和恢复材料，允许单独重试。
- 锁屏恢复冲突：保留备份与事务，不宣称恢复成功。
- 性能采样失败：结束当前诊断并显示错误，不影响播放。
- 性能报告写入失败：保留内存结果并允许重新导出。
- 登录项修改失败：保留旧设置并显示系统错误。
- 诊断导出失败：不修改内部状态，允许选择新位置重试。

所有面向用户的错误必须说明受影响的功能和下一步操作。任何页面级错误都不得清除其他页面的有效状态。

## 测试

### 锁屏

锁屏自动化测试只使用临时目录、伪造 manifest、伪造 `Index.plist` 和依赖注入的恢复器，绝不访问或修改开发机真实壁纸目录。覆盖：

- 只读首次探测和空候选引导；
- 明确选槽与修改确认；
- 主显示器自动同步、媒体去重和主显示器切换；
- 无分配、离线和缺失媒体等待状态；
- 未知系统版本、外部 sidecar、写入失败和配置损坏；
- 关闭恢复、恢复冲突、备份保留和重试；
- 应用窗口关闭与正式终止生命周期。

### 性能

使用可控采样器和虚拟时钟覆盖：

- 每秒采样和最近 60 秒窗口；
- 30 秒诊断、进度、取消和单一完成报告；
- 平均值与峰值聚合；
- 原子报告写入、失败后内存结果保留；
- 硬件/系统元数据和隐私字段约束；
- 页面销毁停止实时采样，应用退出取消诊断。

### 设置与组合

覆盖默认值、`UserDefaults` 持久化、登录项失败回滚、低电量策略即时生效和诊断脱敏。三个页面均包含状态模型测试和 SwiftUI 渲染烟雾测试。生产组合测试验证每个服务只创建一次，主窗口关闭不会停止桌面运行时或锁屏观察。

## 完成门禁

- 完整 `swift test` 零失败；
- `WallumeApp`、`wallume-runtime`、`wallume-media` 和 `wallume-restore` 四个 Release 产品构建成功；
- 当前机器完成一次实际 30 秒参考诊断并记录硬件、系统和场景；
- `git diff --check` 无输出；
- 完成性审查无未解决 Critical 或 Important 问题；
- 只本地合并，第四阶段全部完成前不推送远端。

## 延后范围

音量控制、语言切换、缓存清理、图库重建、完全重置、最终本地化、窗口与导航状态恢复以及最终 UI 验收继续留给后续第四阶段收尾批次。基础款 M1、macOS 14 性能基线作为未来兼容性验证项，不阻塞本批工程完成。
