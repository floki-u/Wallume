# Wallume（壁光）产品与技术设计

日期：2026-07-10
状态：已由产品所有者确认
许可证：Apache License 2.0

## 1. 项目概述

Wallume 是一款面向 Apple Silicon、macOS 14 及以上版本的开源动态视频壁纸应用。它以轻量菜单栏应用运行，允许用户导入视频、按显示器设置桌面动态壁纸，并将主显示器当前视频同步到 macOS 的动态锁屏。

项目从零重新实现。`LiveWallpaperMacOS` 仅作为功能行为和已知问题的研究资料，不复制其代码、资源、品牌、Bundle ID 或 Git 历史。Wallume 使用独立目录、独立 Git 历史和 Apache-2.0 许可证。

## 2. 已确认的产品约束

- 只支持 Apple Silicon。
- 最低系统版本为 macOS 14。
- 首发支持 macOS 14、15、26 的最新小版本。
- 通过 GitHub Releases 和 Homebrew Cask 分发，不进入 Mac App Store。
- 应用为非沙盒应用，因为动态锁屏同步需要访问用户目录下的 macOS Aerial 资源。
- 动态视频锁屏是首版必需功能，不是实验功能。
- 不修改 `/System`，不接触系统认证或解锁流程，不要求 root。
- 导入时允许一次性转码，以换取更低的长期播放开销。
- 每块显示器可以使用不同桌面视频；锁屏始终同步主显示器当前视频。
- 产品名为 `Wallume`，中文名为“壁光”。
- 默认 Bundle ID 为 `app.wallume.Wallume`。

## 3. 目标与非目标

### 3.1 目标

- 用单进程架构实现低内存、低 CPU 的硬件解码视频壁纸。
- 保留参考项目中有效的壁纸库、多显示器、缩放、音量、轮播、随机、暂停、电源和恢复功能。
- 安全地同步动态锁屏，并能在失败、崩溃、系统升级和卸载时恢复系统原状态。
- 提供简洁但可扩展的 macOS 原生界面，后续增加功能不重做窗口结构。
- 建立可重复的性能基准和发布门槛，不使用未经验证的性能宣传。

### 3.2 非目标

- 首版不提供账号、云同步、在线壁纸商店、社交功能或遥测。
- 首版不支持 Intel Mac、Windows 或 Linux。
- 不模拟或替换 macOS 解锁界面。
- 不通过注入系统进程、修改系统签名文件或关闭系统安全功能实现锁屏。
- 不强制依赖 Python、ffmpeg、Homebrew Formula 或常驻 daemon。

## 4. 总体架构

Wallume 使用纯 Swift 单进程架构。菜单栏、按需打开的主窗口、多显示器壁纸窗口和播放器均属于同一应用进程。

### 4.1 核心模块

#### AppShell

- 创建 `NSStatusItem` 和菜单栏弹窗。
- 管理主窗口的创建、关闭和销毁。
- 负责登录启动、启动恢复和安全模式入口。
- 从 `FeatureRegistry` 构建稳定的侧栏导航。

#### FeatureRegistry

- 每个功能模块提供稳定 ID、标题、图标和页面构造器。
- 首版注册图库、显示器、锁屏、性能和设置五个模块。
- 后续自动化、播放列表或在线来源只能以新增模块方式接入，不修改窗口壳层。

#### WallpaperRuntime

- 监听显示器、Space、睡眠、唤醒、电源和前台应用事件。
- 按显示器 UUID 管理 `DisplaySession`。
- 创建位于桌面图标下方的无边框 AppKit 窗口。
- 协调播放器共享、暂停、恢复和异常降级。

#### DisplaySession

- 保存显示器 UUID、视频 ID、缩放模式、音量和暂停策略。
- 显示器拔出时进入休眠状态，不丢失配置。
- 显示器重新连接后恢复对应配置。

#### VideoResourcePool

- 缓存并复用 `AVAsset`、播放器和必要的媒体元数据。
- 多块显示器播放同一视频时共享播放器和解码资源，仅创建额外 `AVPlayerLayer`。
- 在内存压力、长时间暂停或资源无人使用时主动释放对象。

#### MediaImporter

- 校验 `.mp4` 和 `.mov` 输入。
- 使用 AVFoundation 与 VideoToolbox 流式转码为带 `hvc1` 标签的 HEVC `.mov`。
- 根据目标显示器按需生成 1080p、1440p 或 4K 变体。
- 生成小尺寸缩略图和锁屏静态封面。
- 单任务排队执行，支持进度、取消、失败重试和断点清理。

#### LockScreenSync

- 为 macOS 14、15、26 提供独立版本适配器。
- 发现 Aerial 视频槽和 `Index.plist` 的实际结构。
- 执行预检、备份、事务写入、验证、刷新和回滚。
- 管理应用内卸载、Homebrew 卸载和独立恢复工具。

#### SettingsStore

- 简单偏好保存到 `UserDefaults`。
- 壁纸库、显示器映射和事务状态保存为强类型 Codable JSON。
- 所有 JSON 使用临时文件、`fsync` 和原子重命名写入。
- 配置升级使用显式 schema 版本与迁移器。

### 4.2 数据流

```text
用户导入视频
  -> 输入校验
  -> HEVC 硬件转码
  -> 生成缩略图与静态封面
  -> 原子写入媒体库和索引
  -> 用户应用到目标显示器
  -> WallpaperRuntime 更新 DisplaySession
  -> VideoResourcePool 选择或共享播放器
  -> 主显示器视频提交给 LockScreenSync
  -> LockScreenSync 事务更新 Aerial 锁屏资源
```

锁屏同步失败不会回滚桌面壁纸。UI 分别显示桌面状态和锁屏状态，允许用户单独重试或恢复。

## 5. 功能范围

### 5.1 壁纸库

- 导入单个 `.mp4`、`.mov`，或批量导入整个文件夹。
- 展示缩略图、名称、分辨率、帧率、时长、编码和文件大小。
- 识别并复用已经符合要求的 HEVC `hvc1` 文件，避免无意义重编码。
- 转码任务显示进度，支持取消和失败重试。
- 软件管理内部媒体库；原文件默认保留，只有用户明确操作时才删除。
- 支持在 Finder 中查看媒体库、删除单个壁纸和重建索引。

### 5.2 桌面播放

- 按显示器独立设置壁纸。
- 支持填充、适应、拉伸、居中、高度填充五种缩放模式。
- 支持静音和音量控制，默认静音。
- 支持可立即更新的顶部渐变暗角。
- 支持顺序轮播、随机轮播和 1 分钟至 24 小时的自定义间隔。
- 支持启动时随机和睡眠唤醒后随机。
- 支持前台应用非 Finder 时暂停。
- 支持锁屏、低电量模式和用户配置的电池策略。
- 正确处理 Space 切换、睡眠唤醒、显示器热插拔和主显示器变化。

### 5.3 动态锁屏

- 锁屏同步主显示器当前视频。
- 显示未初始化、准备中、已同步、需要修复、已暂停写入等明确状态。
- 提供初始化引导，引导用户在系统设置中下载并选择一个专用 Aerial 壁纸槽。
- 提供重新同步、检查状态、恢复系统壁纸和导出诊断。
- 系统升级到未知版本时禁止新写入，但继续提供状态检查和保守恢复。

### 5.4 系统功能

- 登录启动由用户主动开启。
- 支持系统语言、简体中文和英文。
- 支持清理缩略图缓存、重建媒体库和完全重置。
- 不主动请求辅助功能权限。
- 不包含遥测、广告或后台网络请求。

## 6. 动态锁屏安全设计

### 6.1 已确认的系统位置

在 macOS 26.5.2 实机和现有开源实现中确认的路径如下：

```text
Aerial 视频槽：
~/Library/Application Support/com.apple.wallpaper/aerials/videos/<Aerial-UUID>.mov

Aerial 清单（默认只读）：
~/Library/Application Support/com.apple.wallpaper/aerials/manifest/entries.json

桌面与锁屏选择状态：
~/Library/Application Support/com.apple.wallpaper/Store/Index.plist

冷启动锁屏封面：
/Library/Caches/Desktop Pictures/<用户-GeneratedUID>/lockscreen.png
```

这些路径属于私有实现细节。每个系统适配器必须在运行时发现并验证结构，不能假定未来系统继续保持相同路径或 plist schema。

### 6.2 修改范围

- 不修改 `entries.json`；它只用于读取 Aerial UUID 和显示名称。
- 用户明确选择一个已下载 Aerial 作为 Wallume 专用槽。
- 只修改专用槽的视频文件、`Index.plist` 中与当前锁屏选择有关的节点，以及 Wallume 创建或接管的 `lockscreen.png`。
- 不使用“第一个找到的视频”或模糊文件匹配。
- 不修改其他显示器、其他 Space 或无关壁纸节点。

### 6.3 第三方修改检测

写入前扫描目标文件旁的备份后缀、已知事务标记和哈希状态。如果发现其他动态壁纸软件留下的备份、目标槽与 Apple 清单不一致或当前状态无法解释，Wallume 禁止写入并引导用户先恢复或重新下载 Aerial。

Wallume 的文件使用 `app.wallume.Wallume` 派生的唯一后缀，不覆盖其他工具的备份文件。

### 6.4 事务步骤

1. 检测系统版本并选择对应适配器。
2. 发现专用 Aerial 槽和所有将被修改的配置节点。
3. 验证权限、磁盘空间、视频编码、时长和可播放性。
4. 计算原文件 SHA-256、大小和修改时间。
5. 创建主备份、恢复备份和事务清单。
6. 将事务清单以 `prepared` 状态写入磁盘并 `fsync`。
7. 将新内容写入目标目录内的临时文件。
8. 重新校验临时文件。
9. 使用原子重命名替换视频和配置。
10. 生成并原子替换冷启动封面。
11. 只刷新 `WallpaperAgent` 和 `WallpaperAerialsExtension`。
12. 重新读取目标文件和配置，验证写入结果。
13. 将事务标记为 `committed`；任一步失败则进入回滚。

### 6.5 备份策略

每次首次接管系统槽时创建两份原始备份：

- 主备份：`~/Library/Application Support/Wallume/SystemBackups/<transaction-id>/`
- 恢复备份：与 Aerial 槽同目录，使用 `.app.wallume.Wallume.original.<sha256>.bak` 后缀

`~/Library/Application Support/Wallume/Transactions/<transaction-id>.json` 是唯一权威恢复清单。它记录受限目标路径、原始与 Wallume 写入哈希、备份位置，以及 `Index.plist` 的窄范围前后值；恢复前必须通过路径、所有权和校验和验证。与 Aerial 槽同目录的恢复备份不保存第二份清单：它只提供应用被删除后仍可发现的恢复锚点。独立恢复工具扫描该备份并查找对应的 Wallume 事务日志；任一方缺失、校验失败或无法解释时均停止自动恢复并保留所有证据。

Wallume 不覆盖已有备份。备份校验失败时禁止继续写入。

### 6.6 比较后恢复

回滚和卸载都使用 compare-and-restore 规则：

- 当前 Aerial 文件哈希仍等于 Wallume 写入哈希时，才恢复原视频。
- 当前文件已被系统重新下载或被用户更改时，不覆盖新文件。
- `Index.plist` 只恢复 Wallume 修改过且当前值仍等于 Wallume 写入值的节点。
- 不用历史 `Index.plist` 整文件覆盖当前文件。
- `lockscreen.png` 只有在哈希仍属于 Wallume 时才恢复或删除。
- 发现冲突时保留备份，生成可读诊断并停止自动处理。

### 6.7 崩溃恢复

应用启动时先检查事务日志：

- `prepared` 或 `writing` 状态表示上次操作未完成，立即执行保守回滚。
- `committed` 状态执行健康检查，不重复写入。
- 连续恢复失败时停止锁屏写入，保留桌面播放并进入需要人工处理的安全状态。

安全边界：锁屏事务使用跨进程文件锁串行化 Wallume 写入；权威事务日志中的路径必须精确匹配允许位置，并逐级以 no-follow 方式拒绝已有 symlink。清理项先移入同父目录、事务专属且权限为 `0700` 的目录，再按 inode 身份通过 `openat`/`fstatat`/`unlinkat` 删除并 `fsync` 父目录。该机制防护 Wallume 并发、崩溃和非恶意外部改写；macOS 没有“比较 inode 并原子 unlink”的原语，因此不承诺抵御主动的同 UID 攻击者在最后 syscall 窗口精准替换私有目录项。

### 6.8 卸载与残留清理

应用提供“恢复系统壁纸并卸载”向导：

1. 停止桌面播放并保存当前诊断。
2. 按比较后恢复规则恢复 Aerial 视频。
3. 恢复 Wallume 修改的 `Index.plist` 节点。
4. 恢复或删除 Wallume 管理的 `lockscreen.png`。
5. 刷新壁纸组件并验证系统壁纸可以加载。
6. 删除恢复备份和事务清单。
7. 删除转换视频、缩略图、设置、日志和其他 Wallume 缓存。
8. 注销登录启动并退出应用。

Homebrew Cask 的卸载脚本必须在删除应用和 `zap` 数据之前执行相同恢复流程。恢复失败时卸载脚本返回失败并保留备份。

GitHub Release 附带独立、可审阅的 `Wallume Restore.command`。如果用户直接删除 `.app`，可以下载该工具恢复和清理。重新安装 Wallume 时也会发现孤立事务日志及其同目录恢复备份，并优先提供恢复。

macOS 不会在用户把 `.app` 拖入废纸篓时向应用发送可靠的卸载回调，因此不能承诺手动删除瞬间自动清理。设计保证这种情况下系统仍可运行、原始备份仍存在，并有独立恢复路径。

## 7. 数据与目录布局

```text
~/Library/Application Support/Wallume/
  Library/
    Originals/             # 仅用户选择由 Wallume 管理原文件时使用
    Variants/              # HEVC 播放变体
    library.json           # 媒体索引
  State/
    displays.json          # 显示器映射
    runtime.json           # 期望播放状态
    schema.json            # 数据 schema 版本
  LockScreen/
    transactions/          # 当前与历史事务日志
  SystemBackups/           # 系统资源主备份
  Diagnostics/             # 用户主动导出的诊断包

~/Library/Caches/app.wallume.Wallume/
  Thumbnails/
  Metadata/
  ImportWork/
```

缓存可以随时重建。系统备份不能被普通“清理缓存”操作删除，只能在验证恢复成功后清理。

## 8. UI 设计

### 8.1 主窗口

采用单窗口图库方案。左侧固定导航包含：

- 图库
- 显示器
- 锁屏
- 性能
- 设置

右侧显示当前模块页面。侧栏和窗口壳层长期稳定，功能模块通过 `FeatureRegistry` 注册。

### 8.2 图库

- 顶部提供搜索和导入。
- 卡片显示缩略图、名称、分辨率和编码。
- 当前播放卡片明确标识目标显示器。
- 底部状态栏显示主显示器、缩放、音量及桌面/锁屏同步状态。
- 使用惰性网格，只加载可见缩略图。

### 8.3 菜单栏弹窗

只保留高频操作：

- 当前壁纸预览与暂停/恢复。
- 锁屏同步状态和开关。
- 节能模式。
- 音量/静音。
- 打开壁纸库和退出。

弹窗不加载完整媒体库。主窗口关闭后销毁功能页、搜索索引和图片缓存。

### 8.4 风险提示

锁屏页始终展示：

- 当前专用 Aerial 槽。
- 最近一次备份时间和校验状态。
- 最近一次同步结果。
- 恢复系统壁纸入口。
- 卸载前恢复入口。

任何系统文件写入前，UI 必须说明修改范围并取得用户明确确认。

## 9. 性能与内存设计

### 9.1 媒体策略

- 使用 VideoToolbox 硬件编码 HEVC。
- 播放时使用 Apple Media Engine 硬件解码。
- 根据显示器实际需求选择最接近的本地分辨率变体。
- 原视频超过 60 fps 时输出 60 fps；节能模式使用 30 fps 变体。
- 转码单任务执行并使用流式读写。
- 桌面和锁屏复用同一兼容 HEVC 文件。

### 9.2 运行时策略

- 相同视频多显示器共享播放器和解码资源。
- 不使用固定频率轮询；优先使用系统通知和事件。
- 前台应用遮挡、锁屏或低电量状态下暂停。
- 长时间暂停后释放预缓冲和非必要解码资源。
- 内存压力时优先清空缩略图、元数据和未使用媒体对象。
- UI 关闭后只保留菜单栏与播放运行时。

### 9.3 性能门槛

以基础款 M1、macOS 14 为最低基准设备：

- 单屏 1080p/30 fps、UI 关闭：RSS 不超过 80 MB，平均 CPU 不超过 5%。
- 单屏 4K/30 fps、UI 关闭：RSS 目标不超过 120 MB，平均 CPU 不超过 7%。
- 暂停或锁屏后：CPU 接近 0%，GPU 不持续渲染。
- 双屏播放同一视频：内存增量不超过单屏的 25%。
- 导入转码峰值内存不超过 300 MB。

这些指标是测试和发布门槛，不在未经对应硬件验证前用于营销。

## 10. 错误处理与安全模式

- 视频无法解码时隔离该媒体项并恢复上一张有效壁纸。
- 配置损坏时保留损坏副本，从最后一次有效快照恢复。
- 连续异常退出后进入安全模式：暂停视频、显示静态封面、停止锁屏写入。
- 锁屏错误不影响桌面播放。
- 未知系统版本、第三方冲突、备份损坏、磁盘不足或权限异常均阻止写入。
- 日志不记录视频内容、用户名之外的个人数据或无关文件路径。
- 诊断默认只保存在本地，由用户主动导出。

## 11. 测试与发布门槛

### 11.1 自动测试

- 配置 schema 与迁移。
- 文件名、Unicode、空格和多个点号。
- 媒体校验与 HEVC 变体选择。

## 13. 研究依据

- Apple `NSWorkspace.setDesktopImageURL` 公开 API 只支持桌面图片，不直接支持任意锁屏视频。
- Apple Screen Saver 框架只能提供屏幕保护程序，不能单独满足“同一视频成为系统动态锁屏”的产品要求。
- macOS 14 以后内置 Aerial 壁纸与锁屏使用用户目录下的 `com.apple.wallpaper` 数据。
- `Wallpaper-Sync` 项目证明替换已下载 Aerial 视频槽并更新 Idle 选择可以实现动态锁屏。本项目仅研究其行为与系统位置，不复制其实现。
- 当前开发机 macOS 26.5.2 已只读确认 Aerial、Store 和冷启动封面目录存在，且实际 `Index.plist` 同时包含 Displays、Spaces、Desktop 和 Idle 分支。

## 14. 设计结论

Wallume 采用单进程、纯 Swift、硬件 HEVC 编解码架构，以最低日常资源开销为首要技术目标。动态锁屏通过受控 Aerial 槽实现，并由版本适配、事务日志、双重备份、比较后恢复、卸载钩子和独立恢复工具共同保护系统状态。

首版范围已经固定。后续实施必须先建立安全的锁屏事务原型和性能基线，再扩展完整图库与 UI；不得先完成视觉功能后补做恢复机制。
