# Wallume 阶段二：媒体库与 HEVC 导入器设计

日期：2026-07-15

## 1. 目标与边界

阶段二建立可由未来 AppKit UI 复用的媒体库和导入器，并提供 `wallume-media` 命令行工具用于实机验证。它只处理媒体导入和管理，不创建桌面壁纸窗口、不改变显示器配置，也不触发锁屏写入。

本阶段支持单个 `.mp4` 或 `.mov` 文件，以及递归导入目录。每个成功导入项生成一个 Wallume 管理的 HEVC `hvc1` `.mov` 播放变体、一张缩略图和一张锁屏静态封面。原始文件始终保留在用户选择的位置，Wallume 不复制、移动或删除它。

不在本阶段实现多分辨率变体、播放运行时、UI、在线来源、媒体编辑、原文件托管或索引重建命令。

## 2. 决策

- 每个媒体项只生成一个变体：最长边最高 3840 像素、帧率最高 60 fps。
- 变体使用兼容 macOS 播放与锁屏同步的 HEVC `hvc1` `.mov`；如果输入已经符合目标编码、容器、尺寸和帧率约束，仍复制到 Wallume 管理的变体目录并验证，而不是引用用户原文件。
- 以完整源文件 SHA-256 去重，而不是以路径、文件名、大小或修改时间去重。哈希相同的导入直接返回既有媒体项，不生成第二组派生产物。
- 导入任务全局串行。命令行进程内不并行转码；以后 UI 和后台队列复用同一调度器。
- 单个失败不影响目录批量导入中的其他文件。命令以非零状态退出，只要有一个输入失败或被取消；已成功的条目保持可用。
- 删除仅删除 Wallume 拥有的变体、缩略图、封面和索引记录，永不触碰原文件。

## 3. 目录与所有权

```text
~/Library/Application Support/Wallume/
  Library/
    Variants/<media-id>.mov
    library.json
~/Library/Caches/app.wallume.Wallume/
  Thumbnails/<media-id>.jpg
  Metadata/<media-id>.jpg
  ImportWork/<task-id>/
```

`Library/Variants` 和上述缓存目录中的文件均由 Wallume 独占管理。`library.json` 是唯一权威媒体索引，使用阶段一已有的临时文件、同步和原子替换能力写入。导入临时目录仅保存尚未提交的文件，任务结束后必须为空。

## 4. 核心模型与接口

`MediaItem` 使用稳定 UUID，并至少包含：源 SHA-256、导入时的源路径、显示名称、源文件大小、视频尺寸、帧率、时长、编码描述、变体相对路径、缩略图相对路径、封面相对路径和创建时间。媒体索引有显式 schema 版本；未来迁移只能通过版本化迁移器进行。

`MediaInspector` 只负责读取输入媒体的容器、视频轨、尺寸、帧率、时长和编码信息。它拒绝没有可播放视频轨、不可读取、受保护或非 `.mp4`/`.mov` 的文件。

`MediaTranscoder` 只负责把通过校验的输入写入调用方给出的暂存路径，并报告进度或取消。生产实现使用 AVFoundation 和 VideoToolbox；测试实现可注入可控的成功、失败和取消结果。完成后，导入器重新检查输出实际是可读的 HEVC `hvc1` `.mov`，并验证尺寸和帧率上限。

`ArtworkGenerator` 从已验证变体生成缩略图和锁屏静态封面。`MediaLibrary` 负责查询、去重、原子注册和删除。`MediaImporter` 协调上述对象，拥有单任务调度和提交/清理规则。

## 5. 导入事务

1. 展开输入为稳定排序的候选文件，跳过不支持的扩展名并在报告中标记。
2. 读取输入的 SHA-256；若索引已有相同哈希，返回该条目，不创建任何文件。
3. 使用 `MediaInspector` 校验输入，并拒绝不可播放或没有视频轨的文件。
4. 在 `ImportWork/<task-id>/` 创建暂存变体、缩略图和封面。
5. 转码或复制到暂存变体，生成两张图片，并重新检查每个产物。
6. 将产物原子移入 Wallume 管理目录，保留可回收的暂存或替换记录。
7. 原子写入包含新 `MediaItem` 的 `library.json`。此步骤是导入的提交点。
8. 只有索引写入成功后才报告成功；否则删除本任务创建的所有未登记产物。

取消、转码失败、产物验证失败、磁盘空间不足或索引写入失败都不得留下已登记但缺少文件的条目。进程在提交前中断时，下次导入前清理过期 `ImportWork` 目录；进程在提交后中断时，索引和产物必须已完整可读。

## 6. 命令行工具

新增 SwiftPM executable：`wallume-media`。

```text
wallume-media import <file-or-directory> [...]
wallume-media list
wallume-media show <media-id>
wallume-media remove <media-id>
```

`import` 输出每个候选文件的结果：`imported`、`duplicate`、`skipped`、`failed` 或 `cancelled`，并输出媒体 UUID 或错误原因。目录导入按稳定路径顺序处理。`list` 和 `show` 是只读命令。`remove` 仅在条目和每个待删路径仍位于 Wallume 允许目录内时执行，并对缺失的自有缓存文件采用幂等清理；任何外部路径或符号链接异常均拒绝删除。

## 7. 错误处理

无法读取源、损坏容器、无视频轨、受保护内容、不支持的扩展名、输出不是 HEVC `hvc1`、空间不足、权限问题和原子索引写入失败都必须给出可读错误。导入报告保留每个文件的独立结果，避免一个坏文件掩盖其他成功导入。

删除时找不到索引条目返回明确的未找到错误。发现索引记录指向 Wallume 目录外或符号链接路径时，停止删除并保留索引记录供后续诊断。

## 8. 测试与验收

- 单元测试覆盖 schema 编码、源哈希去重、稳定目录展开、路径安全、索引原子提交、失败清理、取消清理和删除白名单。
- 使用注入的检查器、转码器和图片生成器覆盖每个事务失败点，证明任何失败均不产生半登记条目。
- 集成测试覆盖一文件、递归目录、重复内容的不同路径、部分失败批次、`list`、`show` 和 `remove`。
- 在 Apple Silicon CI 上构建并运行全部测试。真实 AVFoundation 媒体夹具必须短小、可提交且不包含受限素材。
- 手动实机验收导入一段 `.mp4` 与一段 `.mov`，确认输出可由 AVFoundation 打开，视频编码标记为 `hvc1`，最长边不超过 3840，帧率不超过 60，且原文件内容与路径均未改变。

阶段二完成的判定是：CLI 能完成上述闭环，索引和所有派生产物在取消或失败后保持一致，未来 UI 可以只调用 `MediaLibrary` 和 `MediaImporter` 而不依赖命令行代码。
