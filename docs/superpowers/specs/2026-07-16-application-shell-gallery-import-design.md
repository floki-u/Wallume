# Wallume 第四阶段第一批：应用壳层、图库与完整导入体验设计

日期：2026-07-16

状态：产品所有者已确认交互与技术方向，等待书面规格复核

## 目标与范围

本批建立第四阶段长期稳定的应用壳层，并交付可日常使用的图库与完整导入体验。应用采用 AppKit 生命周期和菜单栏，页面采用 SwiftUI。用户可以通过按钮或拖放导入多个文件和文件夹；文件夹递归扫描子目录，忽略隐藏内容与 package 内容。导入任务串行执行，主窗口关闭后继续在菜单栏后台运行。

本批不实现显示器壁纸更换、锁屏写入、性能页面功能、设置页面持久化 UI 或音量控制。侧栏保留图库、显示器、锁屏、性能、设置五个稳定入口；除图库外，其余模块显示明确的后续批次占位状态。

## 技术架构

新增 `WallumeApp` SwiftPM 可执行产品。AppKit 管理应用生命周期、状态项和窗口所有权；SwiftUI 构建主窗口内容与菜单栏弹窗。

### ApplicationController

`ApplicationController` 是进程级组合根，负责：

- 创建与更新 `NSStatusItem` 和菜单栏弹窗。
- 按需创建、关闭和销毁主窗口及其 SwiftUI 页面树。
- 持有后台 `ImportQueue`，确保关闭主窗口不终止导入。
- 执行首次启动和“启动时打开图库”策略。
- 根据窗口可见性与应用活跃状态决定应用内提示或系统通知。
- 应用退出时检查活动队列，并在用户确认后取消全部、等待清理完成再退出。

首次启动自动打开图库。首次启动之后默认仅驻留菜单栏。第一批保存最小启动标记，并为第三批设置页预留“启动时打开图库”偏好接口。

### FeatureRegistry

`FeatureRegistry` 为每个模块提供稳定 ID、标题、系统图标和页面构造器。第一批注册：

- 图库：完整可用。
- 显示器、锁屏、性能、设置：显示该模块将在后续批次开放，不提供会误导用户的空操作。

侧栏结构在后续批次保持不变，模块能力通过替换页面构造器接入。

### GalleryStore

`GalleryStore` 是主线程可观察状态，负责媒体库加载、搜索、选择、刷新、详情打开和删除。媒体导入成功后按单项事件增量刷新；队列结束时再执行一次权威索引重载。

图库使用惰性网格，只加载可见缩略图。搜索匹配显示名称、分辨率和编码，不建立常驻全文索引。索引读取失败时保留错误状态并展示恢复建议，不自动覆盖或重建损坏索引。

### ImportScanner

`ImportScanner` 把文件选择器或拖放得到的 URL 展开为稳定候选列表：

- 支持多个 `.mov` 和 `.mp4` 文件。
- 递归扫描目录及其非隐藏子目录。
- 忽略隐藏文件、隐藏目录和 package 目录内容。
- 通过标准化文件 URL 去重。
- 按本地化标准路径稳定排序。
- 单个目录无法读取时记录扫描警告，继续扫描其他输入。
- 如果没有候选媒体，向用户显示“未找到可导入视频”。

选择中不支持的普通文件静默忽略。扫描结果与警告进入任务抽屉，不阻塞可访问候选项。

### MediaImporter 扩展

现有 `MediaImporter` 的安全边界继续保持：哈希去重、私有临时目录、暂存产物验证、独占安装、索引最后提交和取消清理。为 UI 增加单项导入接口和事件回调：

- 阶段：哈希检查、检查媒体、转码、生成图稿、提交媒体库和清理。
- 进度：已知时报告当前阶段的 0...1；不能精确测量的阶段显示不确定进度。
- 取消：Swift task cancellation 传播到 AVFoundation 转码；单项接口在清理完成后才返回 `cancelled`。

底层导入器不拥有队列策略。失败后继续、取消当前、取消全部和重试由 `ImportQueue` 决定。

### ImportQueue 与 ImportTaskStore

`ImportQueue` 是独立 actor，严格串行运行候选项，任何时刻最多有一个导入/转码任务。它持有队列项的不可变身份与状态历史，并发布结构化事件。

`ImportTaskStore` 在主线程消费事件，驱动 SwiftUI、菜单栏摘要和通知。状态包括：扫描、等待、执行中、已导入、重复、失败、已取消。每个执行项保存当前阶段、进度、用户提示和诊断文本。

重试失败项会创建新的尝试记录并关联原项；历史失败仍可查看。“重试全部失败项”按原始稳定顺序追加新尝试。

### MediaDetailStore

点击图库卡片打开详情面板，展示封面、名称、源文件位置、分辨率、帧率、时长、编码和文件大小。视频预览不会自动加载；用户点击播放后才创建静音播放器。关闭详情或切换到另一媒体时立即停止并释放播放器。

详情操作包括在 Finder 中显示和删除。Finder 定位失败只显示非阻塞提示。

### MediaUsageChecking

删除前通过 `MediaUsageChecking` 查询持久化的显示器媒体引用。只要任一显示器仍引用目标媒体，删除操作被阻止，并列出相关显示器，提示用户前往显示器页面更换壁纸。引用消失后删除入口自动恢复可用。

第一批尚未交付显示器配置页，因此真实引用读取接口和占位跳转均先建立；未被引用的媒体可以安全删除。删除继续调用现有 `MediaLibrary.remove`，不删除用户原始源文件。

## 界面与交互

### 主窗口

主窗口使用固定侧栏和单内容区。图库顶部包含搜索、“导入文件”和“导入文件夹”。内容区使用惰性缩略图网格，媒体卡片展示缩略图、名称、分辨率和编码。

窗口接受文件和文件夹拖放，语义与选择器一致。拖放或选择后先扫描，扫描到候选项即加入队列；重复选择同一路径不会在同一待处理队列中产生重复项。

### 底部任务抽屉

采用已确认的 A 方案：底部任务抽屉。

- 无任务时隐藏。
- 活动时默认折叠，显示当前文件、整体 `已处理/总数`、当前阶段和进度。
- 展开后显示所有队列项、扫描警告、失败原因和历史尝试。
- 提供“取消当前项”和“取消全部”。
- 失败项提供单独重试，汇总区提供“重试全部失败项”。
- 队列结束显示成功、重复、失败、取消数量和完成提示。

“取消当前项”取消当前底层任务，等待临时产物清理完成后继续下一项。“取消全部”取消当前项，并将所有尚未开始的项标记为取消；已经导入的媒体保留。

单项失败记录可读原因并继续后续文件。重复媒体标记为“已存在”，不计入失败。

### 菜单栏后台体验

主窗口关闭不影响队列。菜单栏状态摘要显示当前项、整体进度和失败提示。弹窗提供：

- 当前导入项目和阶段。
- 整体 `已处理/总数`。
- 取消当前项和取消全部。
- 重新打开图库。
- 队列结束后的结果摘要。
- 退出应用。

只有主窗口关闭或应用不活跃时，队列结束才发送系统通知。应用处于前台且主窗口可见时，只在任务抽屉显示完成提示。通知权限拒绝不影响任何导入功能。

## 数据流

```text
文件选择 / 文件夹选择 / 拖放
  -> ImportScanner 递归、过滤、去重、稳定排序
  -> ImportQueue 添加候选项
  -> 单项 MediaImporter 安全导入与进度事件
  -> ImportTaskStore 更新任务抽屉和菜单栏
  -> 单项成功触发 GalleryStore 增量刷新
  -> 队列结束重载媒体库索引
  -> 前台应用内提示，后台按条件发送系统通知
```

主窗口页面树可以销毁，但 `ApplicationController`、`ImportQueue` 和后台任务状态在进程生命周期内持续存在。重新打开图库时，新的 SwiftUI 页面从 `ImportTaskStore` 当前快照恢复抽屉状态。

## 错误与退出行为

- 文件无权限、文件消失、无法解码、转码失败、磁盘写入失败分别映射为稳定用户提示，并保留底层诊断文本。
- 取消必须等清理完成后才能启动下一项，保证转码任务不重叠。
- 单项失败不停止队列。
- 文件夹部分不可读不丢弃其他可访问候选项。
- 媒体库索引损坏时不自动覆盖。
- Finder 和通知失败不影响媒体库与队列。
- 用户请求退出且队列活动时显示确认。取消退出则维持队列；确认退出则取消全部，等待当前项清理完成后终止进程。
- 应用异常终止后的临时目录清理由已有导入安全机制和后续启动清理完成；本批不声称跨进程恢复未完成的转码进度。

## 测试与验收

### 自动测试

- `ImportScannerTests`：递归目录、隐藏文件/目录、package、扩展名过滤、URL 去重、稳定排序和部分目录读取失败。
- `MediaImporterProgressTests`：阶段事件、可测进度、单项取消、AVFoundation 取消传播和临时/已安装产物清理。
- `ImportQueueTests`：严格串行、失败继续、取消当前、取消全部、重复结果、单项重试和重试全部。
- `GalleryStoreTests`：加载、搜索、刷新、选择、引用阻止删除、引用解除后删除与索引错误。
- `ApplicationStateTests`：首次启动、后续菜单栏启动、窗口销毁后队列保持、通知条件和菜单栏摘要。
- AppKit/SwiftUI 烟雾测试：状态项、主窗口、稳定侧栏、图库网格、抽屉折叠/展开和详情关闭时播放器释放。

### 集成验收

- 全量 `swift test`。
- `WallumeApp`、`wallume-media`、`wallume-runtime` 和 `wallume-restore` 的 release 构建。
- 在隔离临时 HOME 中选择多个真实 `.mov/.mp4` 与嵌套文件夹，验证串行导入、重复识别、失败继续、取消清理和图库刷新。
- 导入期间关闭主窗口，验证菜单栏进度继续，完成后按条件通知，并能重新打开窗口查看完整结果。
- `git diff --check`。

所有自动和集成测试不得读写用户真实的 macOS 壁纸目录。UI 测试使用隔离媒体库和注入依赖。

## 后续批次边界

第四阶段后续批次依次交付：

1. 显示器配置、壁纸分配和播放控制。
2. 锁屏、性能和设置页面。
3. 本地化、状态恢复、UI 验收和第四阶段收尾。

第一批的稳定导航、后台任务与依赖接口供后续页面复用，不在后续批次重新设计应用壳层。
