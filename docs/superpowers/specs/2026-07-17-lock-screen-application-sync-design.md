# Wallume 应用内锁屏同步设计

日期：2026-07-17

## 目标与边界

本子批把既有锁屏安全事务与恢复能力接入 `WallumeApp`，提供首次配置、主显示器自动同步、明确状态、关闭恢复和诊断入口。锁屏失败不得改变桌面分配或播放。自动化测试不得访问开发机真实壁纸目录。

## 组件

- `LockScreenConfigurationStore`：版本化原子 JSON，只保存启用意图、已选 Aerial ID、活动事务 ID、最近媒体与结果。配置损坏时保留文件并禁止写入。
- `LockScreenSyncService`：应用级串行命令服务，组合 probe、transaction、recovery、媒体库与主显示器快照。
- `LockScreenFeatureStore`：向 SwiftUI 发布不可变页面状态，提供刷新、启用、重试、重新同步和恢复命令，并生成不含文件路径的本地诊断快照。
- `LockScreenView`：呈现设置引导、风险确认、同步状态、备份摘要和恢复入口，不直接操作文件系统。

事务日志仍是系统写入和恢复事实的唯一权威来源；配置中的活动事务 ID 只是引用。

## 首次配置

首次进入只执行只读探测。页面显示 macOS 代际、写入许可、manifest 与 `Index.plist` 状态、候选槽和外部 sidecar。没有候选时引导打开系统壁纸设置，返回后由用户刷新。

用户必须明确选择一个候选槽。确认界面列出专用视频槽、`Index.plist` 选择节点、锁屏封面和恢复保障；确认后才保存启用意图并尝试首次同步。Wallume 永不默认选择第一个槽。

## 启动对齐

服务先加载配置并调用 `RecoveryCoordinator.inspect()`，再允许任何写入：

- 配置引用的 `committed` 事务继续作为当前锁屏状态。
- `prepared`、`writing` 或 `restoring` 事务先完成恢复，再按当前主显示器重新同步。
- `conflicted` 或多个无法唯一归属的活动事务进入需要修复并停止新写入。
- 如果事务提交后、配置保存前崩溃，只有唯一候选且 Aerial ID 与用户已选槽一致时，服务才能自动恢复原始状态后重新同步；否则等待用户处理。
- 未知系统版本保留只读检查和恢复，但禁止新安装。

## 自动同步

启用后服务观察主显示器和完整分配快照。有可用媒体时使用该媒体的 HEVC `variantURL` 与 `coverURL` 构造事务请求。

- 相同媒体已同步时不重复写入。
- 主显示器或其壁纸改变时切换同步目标。
- 无分配、离线、媒体索引缺失或文件不可用时进入等待，不写入也不恢复。
- 等待条件解除后自动重新评估。

既有事务的备份不得被后续安装覆盖。切换媒体时先持久化只引用既有事务和媒体 ID 的恢复标记，再依据活动事务完整恢复原始 Aerial、封面和 `Index.plist`，验证无冲突后再创建新事务。恢复标记只表示恢复已开始，不是完成证明；重启时必须有同一事务日志可供幂等恢复/终态清理，缺失或不相关的日志一律失败关闭，不清除引用也不重新安装。

## 关闭与恢复

关闭同步必须执行恢复。只有恢复报告无冲突、原始状态验证完成并完成允许的备份清理后，配置才标记关闭。外部修改、备份不一致或恢复冲突会进入需要修复，保留事务和备份，桌面播放继续。

页面操作包括：刷新检测、打开系统壁纸设置、确认启用、重新同步、恢复系统壁纸和导出锁屏诊断。所有错误说明受影响范围和下一步操作。

## 生命周期

主窗口关闭不停止已启用的锁屏观察。正式退出时不启动新命令；如果事务或恢复已进入文件写入阶段，应用等待其到达安全终点。独立 `wallume-restore` 始终保留为应用外恢复路径。

## 测试与门禁

使用临时目录、伪造 manifest/`Index.plist`、可控媒体库和注入式 probe/transaction/recovery 覆盖首次探测、选槽确认、去重、主显示器切换、等待、启动恢复、孤儿事务、冲突、关闭恢复和生命周期。完成时运行全量测试、四产品 Release 构建、`git diff --check` 和完成性审查。
